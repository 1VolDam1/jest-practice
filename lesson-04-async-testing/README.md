# Лекция 4. Тестирование асинхронного кода

Практика к теме асинхронных тестов: `async/await`, ожидание промиса через `return`, матчеры `resolves` / `rejects` и страховка `expect.assertions`. Главная опасность темы — **ложноположительный** («обманчиво зелёный») тест, который проходит, не дождавшись проверки.

Два задания, для каждого — своя пара «функция + тест» в `src/`:

- `divideAsync.js` / `divideAsync.test.js`
- `fetchUserById.js` / `fetchUserById.test.js`

> В этой лекции вы сами пишете асинхронные функции (они возвращают промис) и тестируете их. 

> **Одно правило на оба задания.** Перед `expect(...).resolves` и `expect(...).rejects` обязателен `await` (или `return` промиса). Без него тест станет зелёным, не выполнив проверку.

---

## Задание 1. `divideAsync` — асинхронное деление

`divideAsync(a, b)` — **асинхронная** функция (`async`).

**Спецификация.**

- если `b === 0` — бросить ошибку `"Деление на ноль"` (в async-функции `throw` превращается в отклонённый промис);
- иначе — вернуть результат `a / b`.

**Тесты.**

- [ ] Обычное деление: `divideAsync(10, 2)` → `5` (проверьте через `await expect(...).resolves.toBe(5)` **или** через `const r = await divideAsync(...)`).
- [ ] Деление на ноль: промис **отклоняется** с ошибкой `"Деление на ноль"` (`await expect(...).rejects.toThrow(...)`).

---

## Задание 2. `fetchUserById` — поиск пользователя

`fetchUserById(id)` — **асинхронная** функция, имитирующая запрос к базе. Массив пользователей `USERS` уже лежит в файле-заготовке, менять его не нужно:

```js
const USERS = [
  { id: 1, name: "Аня" },
  { id: 2, name: "Борис" },
];
```

**Спецификация.**

- найти в `USERS` пользователя с нужным `id`;
- если найден — вернуть его объект (`{ id, name }`);
- если не найден — бросить ошибку `"Пользователь не найден"`.

**Тесты.**

- [ ] Существующий `id`: `fetchUserById(1)` → `{ id: 1, name: "Аня" }` (`resolves.toEqual` — объект сравниваем по содержимому!).
- [ ] Несуществующий `id`: `fetchUserById(999)` → отклонение с `"Пользователь не найден"` (`rejects.toThrow`). Добавьте `expect.assertions(1)` как страховку от забытого `await`.
