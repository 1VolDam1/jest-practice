# Лекция 4. Тестирование асинхронного кода

Практика к теме асинхронных тестов: `async/await`, матчеры `resolves` / `rejects`, мок-функции `jest.fn()` и защита от ложноположительного («обманчиво зелёного») теста.

В этой папке вы работаете с двумя файлами в `src/`:

- `fetchWeather.js` — **заготовка функции**, которую вы реализуете;
- `fetchWeather.test.js` — **заготовка тестов**, которые вы напишете.

---

## Задание: `fetchWeather`

Вы одновременно разработчик и тестировщик: сначала реализуете асинхронную функцию, потом покрываете её тестами — не выходя в настоящую сеть.

### Шаг 1. Реализуйте функцию

`fetchWeather(client, city)` — асинхронная функция запроса погоды.

- если `city` пустой (`""`, `null`, `undefined`) — **сразу** бросить ошибку `"Город обязателен"`, не обращаясь к `client`;
- иначе — вызвать `client.get(city)` и дождаться ответа (это промис);
- ответ имеет вид `{ temp: <число> }`;
- вернуть строку формата `"Москва: 21°C"` (город, двоеточие, температура, `°C`);
- если запрос отклонился (ошибка сети) — не «глотать» ошибку, дать ей проброситься наружу.

> Клиент передаётся аргументом специально — чтобы в тесте подменить его на мок `jest.fn()` вместо настоящего сетевого запроса.

### Шаг 2. Напишите тесты (минимум три)

- [ ] **Успех.** Мок `client.get` возвращает `{ temp: 21 }` через `mockResolvedValue`. Проверьте результат `"Москва: 21°C"` (через `await` + `resolves`) и что `client.get` вызван с городом (`toHaveBeenCalledWith`).
- [ ] **Ошибка сети.** Мок `client.get` отклоняется через `mockRejectedValue(new Error("Сеть недоступна"))` → функция пробрасывает ошибку (`rejects.toThrow`).
- [ ] **Валидация.** Пустой город → ошибка `"Город обязателен"`, и `client.get` **не вызывается** (`not.toHaveBeenCalled`).

> **Не забудьте `await`** перед `expect(...).resolves` / `.rejects` — без него тест зеленеет, не дождавшись проверки.

### Шаг 3. Проверьте

```bash
npm test
```

Добейтесь трёх зелёных тестов. Затем специально «сломайте» функцию (например, уберите `°C`) и убедитесь, что тест на успех краснеет с понятным `Expected` / `Received`. Верните как было.

## Критерии готовности

- [ ] `fetchWeather` реализована по спецификации.
- [ ] Есть три теста: успех, ошибка сети, валидация.
- [ ] В тестах используется мок `jest.fn()` — реальной сети нет.
- [ ] В каждом async-тесте есть `await` перед `resolves` / `rejects`.
- [ ] `npm test` — зелёный.

## Бонус

- Через `test.each` проверьте несколько городов и температур разом.
- Проверьте, что `client.get` вызван ровно один раз (`toHaveBeenCalledTimes(1)`).
